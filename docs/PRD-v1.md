# PICU 脓毒症 CRF 一期原型 PRD

## 1. 目标

一期原型面向医生/研究员，验证“单病种 CRF 结构化填审 + 来源证据查看 + 人工确认”的核心流程。系统基于现有 Excel 调研表生成 CRF 字段配置，使用 Mock 病例和 Mock 来源片段模拟院内数据，不接真实接口。

## 2. 用户与场景

- 医生/研究员：查看待处理病例，补充无法自动提取的字段，确认系统带入值。
- 信息科/研发：查看 CRF 字段、来源系统、输入方式和标注要求，评估后续接口对接。
- 项目负责人：粗看病例完成度、待手填数量、待确认数量和来源覆盖情况。

## 3. 一期范围

- 单病种：省儿童 PICU 脓毒症 CRF。
- 数据来源：EMR/住院病历、LIS/检验、护理/监护、检查/PACS、评分表、随访、来源待确认。
- 字段状态：已自动带入、需手填、需确认、缺失、来源不明确。
- 功能页面：病例工作台、原始资料、CRF 填审、字段映射。

不包含真实 HIS/EMR/LIS/PACS 接口、不包含 OCR、不包含大模型识别、不包含正式数据治理闭环、不包含多病种模板管理。

## 4. 页面与流程

### 病例工作台

展示病例列表、CRF 完成度、待手填数、待确认数、负责人和更新时间。用户从列表进入单病例 CRF 填审。

### CRF 填审

页面按模块组织字段。左侧为模块导航，中间为字段表单，右侧为来源证据。用户可以按字段状态筛选、搜索字段、编辑手填值、确认字段。确认后字段状态更新为“已自动带入”，病例完成度同步更新。

### 原始资料

页面提供两种展示方式。默认“按来源整理”，把同一病例的 EMR、LIS、护理、检查、评分表和随访资料整理成来源卡片，并展示关联 CRF 字段。“原始多表”展示患者基本信息表、诊断与医嘱表、LIS 检验结果表、护理生命体征表、检查报告表、PSS/PIM3 评分表和随访记录表，便于追溯字段来自哪张表。

### 字段映射

展示字段来源和一期输入策略。支持按来源系统、模块、输入方式和关键词筛选，用于后续接口调研与数据治理拆解。

## 5. 数据对象

- `crfTemplate`：CRF 模板，包含模块、字段、选项、数据来源、数据根源、输入方式、标注要求、备注。
- `caseRecord`：病例实例，包含病例基本信息、字段值、字段状态、确认人、更新时间和完成度。
- `sourceEvidence`：来源证据，包含来源系统、文档标题、时间、片段和关联字段。
- `rawTables`：病例原始多表数据，包含表名、来源系统、列、行和关联 CRF 字段。
- `fieldMapping`：由 `crfTemplate.fields` 派生的映射清单，连接 CRF 字段与来源系统。

## 6. 验收要点

- Excel 中 21 个模块可完整出现在模块导航或字段映射中。
- 单病例 CRF 能展示 5 类字段状态。
- 能从病例列表进入 CRF，编辑字段值，确认字段，并看到完成度变化。
- 点选字段后能查看对应来源系统、来源说明和 Mock 来源片段。
- 能查看单病例原始资料，并在“按来源整理”和“原始多表”之间切换。
- 能从原始资料页跳转到关联 CRF 字段。
- 字段映射页能按来源系统、模块、输入方式和关键词筛选。

## 7. 二期方向

- 接真实院内接口，建立字段级接口契约和回填策略。
- 引入 OCR 和大模型识别，用于非结构化病历、检查报告和随访文本。
- 建立数据治理机制，包括字段标准化、缺失值规则、冲突处理、审计追踪和质控报表。
